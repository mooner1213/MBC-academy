# 포트폴리오 정리 가이드

## 1. 이 저장소의 정체성

이 저장소는 단일 서비스 프로젝트가 아니라, 게임 개발 학습 과정을 기록한 아카이브입니다. 
즉, 포트폴리오에서는 "완성된 게임 프로젝트"라기보다 "게임 개발자로 성장하는 과정"으로 보여주는 것이 가장 자연스럽습니다.

## 2. 포트폴리오에서 강조할 핵심 역량

- 게임 기획 문서 작성 능력
- Unity와 C# 기반 프로토타입 구현 경험
- 플레이어, 적, 전투, 스폰, UI 시스템 설계 이해
- 게임 밸런스와 UX에 대한 고민
- VR/최적화 및 렌더링/성능 고려 능력

## 3. 추천 소개 문구

다음 문구는 GitHub와 포트폴리오에서 바로 사용할 수 있습니다.

- 게임 기획과 Unity 기반 프로토타입 구현을 학습하며 성장해온 저장소입니다.
- 기획, 구현, 시스템 설계, 최적화까지 게임 개발 전반을 학습한 과정 기록입니다.
- Unity와 C#를 활용해 게임 구조와 메커니즘을 실습하며 쌓아온 개발 아카이브입니다.
- 게임 개발의 기초부터 성능과 UX를 함께 고려하는 사고를 학습한 기록입니다.

## 4. 가장 중요한 문서

이 저장소에서 포트폴리오로 가장 잘 보이는 문서는 아래입니다.

1. `Unity/unity.md`  
   실제 Unity 실습과 프로토타입 구현 과정을 보여줍니다.

2. `0520/게임기획서.md`  
   기획력과 설계 구조를 보여주는 핵심 문서입니다.

3. `1014/Readme.md`  
   실무형/심화 개념을 학습한 내용을 보여줍니다.

4. `0420/개발환경.md`  
   Git, Unity, 개발 환경 구성 역량을 설명합니다.

## 5. 포트폴리오에서의 시각

이 저장소를 포트폴리오로 보여줄 때는 다음 점을 강조하면 좋습니다.

- 단순한 문서 정리가 아니라, 실습과 성장 과정이 보인다
- 기획과 구현을 함께 경험했다
- 게임 개발의 기본기와 심화 지식을 함께 쌓아갔다
- 완성형 프로젝트가 아니라도, 프로젝트를 구성하는 사고방식이 보인다

## 6. 추천 정리 방식

포트폴리오로 정리할 때는 아래 순서가 가장 깔끔합니다.

1. README에서 전체 소개를 명확히 작성
2. 핵심 문서 3~5개를 대표 문서로 선정
3. 오래된 일자별 메모는 archive처럼 보관
4. 포트폴리오용으로는 '기획 → 구현 → 최적화' 흐름을 강조

## 7. 최종 결론

이 저장소는 "완성된 게임 프로젝트"가 아니라, 게임 개발자로 성장하는 동안 쌓아온 실습과 학습 기록의 아카이브입니다. 
이 점을 포트폴리오로 잘 정리하면, 단순한 기록이 아니라 개발 역량과 학습 의지가 드러나는 자료로 보이게 만들 수 있습니다.
