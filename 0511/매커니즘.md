# 게임을 구성하는 4대요소

1. **매커니즘** : 게임 절차와 규칙, 게임을 게임답게 만드는 뼈대
2. 미적요소
3. 이야기
4. 기술

### 매커니즘
> 게임세계를 지탱하는 궁극의 청사진 / 껍데기를 모두 벗겨낸 뒤, 비로소 드러나는 공간, 객체

1. 기반 : **공간, 객체**, 속성, 상태 - 게임이 펼쳐지는 무대와 그 안에서 변화하는 요소
2. 상호작용 : **액션과 규칙** - 플레이어가 취하는 행동과 이를 제어하는 시스템의 원칙
3. 변수 : **기술과 운** - 플레이어의 숙련도와 예측 불가능한 요소가 재미를 만듦

### 1. 공간
> 게임을 설계하는 보이지 않는 차원의 건축학

**공간은 게임안의 다양한 장소와, 그 장소들끼리 어떻게 연결되어있는지를 규정함**
* 장소 : n차원의 좌표위에 존재하는 독립된 장소
* 연결 : 장소와 장소를 잇거나 차단하는 위상학적 엣지

**공간의 종류**
* 불연속적 공간 : 타일, 헥사곤, 체스보드와 같이 **이동과 위치가 특정 단위로 딱딱 끊어지는 통제**된 구조
* 연결적 공간 : 3D오픈월드나 물리엔진 기반 맵처럼 **미세한 단위의 자유로운 궤적과 이동이 가능**한 구조

#### 연결의 위상학

* 직접 연결 : 포탈, 복도 등 두 장소가 물리적 / 시스템적으로 즉시 이어지는 상태
* 조건부 연결 : 숨겨진 방, 미로처럼 특정한 경로를 거쳐야만 도달 가능
* 단절(미연결) : 시각적으로는 보이나, 물리적으로 갈 수 없는 배경이나 격리된 더미 공간

### 포개진 공간
> 공간안의 공간. 즉 연속적 2차원인 외부공간을 베이스로 그안에 무수히 많은 공간을 품는다.

**왜 포개는가?** - **무한히 넓은 현실**을 **한정된 리소스**내에 **경제적이고 효과적**으로 표현하기 위한 **게임 디자인의 핵심 트릭**

### 차원전환 프로세스

1. 공간의 압축 : 거대한 외부 공간을 추상화된 좌표계로 압축한 정보공간
2. 위상 단절과 연결 : 기존공간과 단절되고 새로운 공간의 데이터를 로딩
3. 인스턴스 전개 : 완전히 독립된 규칙이 적용

### 가장 작은 공간, 0차원

**모든 게임은 일정의 정보와 상태를 가지며, 이것은 어딘가에 존재한다.**
> 물리적 형태없이 0차원의 한 점에서 처리되는 데이터 공간

**정보와 심리의 공간**
* 출제자의 마음 : 기획의도 및 룰
* 대화공간 : 0차원 상태 값, 게임 엔진
* 질문자의 마음 : 유저의 인지 모델 및 경험

> 0차원의 데이터는 단순히 서버에 머무는 것이 아니라, 출제자와 질문자의 심리적 공간을 동기화하는 대화의 장으로 기능

### 청사진 구조

* 공간 & 객체 : 어디에 무엇이 존재하는가?
* 속성 : 그것을 정의하는 데이터는 무엇인가?
* 상태 : 현재 어떠한 모습을 하고 있는가?
* 비밀 : 누가 그 정보를 볼 수 있는가?

### 공간과 객체

Rule 1. 모든 공간은 반드시 객체를 포함하고 있다.

Rule 2. 객체는 일반적으로 하나 이상의 속성을 가지며, 그 중 한가지는 게임 공간 내의 현재 위치이다.

### 속성 : 데이터의 범주화

**정의** : 속성이란, 객체의 정보를 나타내는 범주이다.
> 단순한 "존재" 였던 객체에 생명력과 물리적 한계를 부여하는 데이터 슬롯이다.

**속성의 두가지 차원**
* **정적(Static)** : 게임 중 변하지 않는 속성 (최대 체력, 기본 직업, 고유 식별자)
* **동적(Dynamic)** : 게임중에 실시간으로 변할 수 있는 속성 (현재 체력, 현재 적용된 버프, 남은 탄약)

### 상태 : 현재의 현실

**규칙** : 각 속성은 현재 상태를 갖는다.
> 속성이 정보의 그릇이라면, 상태는 그 그릇에 지금 이 순간 담겨있는 내용물이다.

### 매커니즘의 문법 : 동사와 형용사
> 객체가 게임 매커니즘의 동사라면, 속성과 그 상태는 형용사다.

### 정보의 비대칭 : 비밀의 개입

**매커니즘은 단순히 데이터가 존재하는 것만으로 완성되지 않는다. 누가 그 데이터를 볼 수 있는가가 게임의 본질을 결정한다.**

* 모두에게 공개되는 속성 / 상태 정보
* 모두에게 공개되지 않는 속성 / 상태 정보
* 일부에게만 공개되는 속성 / 상태 정보

### 게임 아키텍처의 3대 핵심 원칙
* 존재의 필수 조건
* 정보의 변화
* 비밀과 전략

### 액션
> 액션은 게임 매커니즘의 '동사'이다.

* 주체 - 플레이어
* **동사 - 무엇을 할 수 있는가?**
* 객체 - 게임 세계

**액션은 단순한 조작이 아니다. 플레이어가 게임 세계에 개입하고 변화를 일으키는 유일한 언어이다.**

1. **활동적 액션 : 플레이어가 실행하는 가장 기초적인 개입**
  * 직접성 : 객체를 이동시키거나 점프시키는 등 즉각적인 물리적 변화를 생성
  * 규칙의 명시성 : 게임 시스템이 명확하게 정의하고 허용한 기본동작

2. 결과적 액션 : 본직적으로 시스템 규칙에 명시되어 있지않지만, 게임을 플레이하는 과정에서 자연스럽게 파생되는 액션과 전략

### 창발적 액션 극대화 5가지

1. 동사의 확장 : 더 많은 동사를 부여
2. 상호작용의 다변화 : 다양한 사물에 작동하는 동사 설계
3. 목표의 유연성 : 단일 목표를 여러 방법으로 달성 가능하게 구조화
4. 제약의 변형 : 부가효과를 통해 게임 내 제약을 지속적으로 변화시킴
5. 주체의 다수성 : 개입 가능한 수많은 주체의 배치
