### 선형성장 vs 지수성장 모델링
* 선형성장
  * 매일 정직하게 저금하는 통장과 같다.
  * 모든 레벨에서 요구량이 일정해서 유저가 미래를 완벽히 예측할 수 있다.
  * 안정적이나, 후반부로 갈수록 성장의 성취감이 무뎌지고 지루할 가능성이 높다.
 
* 지수성장
  * 굴릴수록 커지는 스노우볼 모델
  * 초반에는 쾌속성장을 통해 도파민을 자극하고, 후반에는 허들을 높여 콘텐츠 소모속도를 제어한다.
  * 방치형게임이나 mmorpg 에서의 핵심 척추가 되는 가장 대중적인 모델이다.
 
### 성장의 선순환 구조
* 도전과 획득 : 몬스터 사냥 및 퀘스트 수행을 통한 경험치 수급
* 능력의 확장 : 레벨업 시 스텟 상승 및 새로운 스킬 개방
* 콘텐츠 해금 : 상위 던전 진입권 획득 및 경제시스템 확장
* 심리적 보상 : 경쟁 순위 상승 및 시각적 레벨 이펙트 피드백

### 경험치 곡선

**EXP(next) = a x Level^b x c**

* a = 계수(Scale) : 전체적인 숫자의 단위를 결정 -> 단위 한번에 조정하는 핸들
* b = 지수(Power) : 곡선의 기울기를 결정 -> 성장의 벽 생성
* c = 상수(Base) : 레벨로 갈때 필요한 최소 시작 경험치 -> 초반 성장의 리듬을 고정하는 역할

### 밸런싱 기획 시 핵심 체크 리스트
* **경험치 인플레이션 주의** : 획득 경험치 대비 요ㅗ구량이 비정상적으로 높지 않은지 엑셀 그래프로 상시 모니터링
* **플레이 타임 대조** : 1레벨 업에 소요되는 실제 물리적 시간이 기획의도와 부합하는지 계산
* **누적 성장비율 분석** : 특정 구간에서 성장이 멈춘 듯한 느낌을 주지 않도록 누적 경험치 곡선을 부드럽게 튜닝
* **소수점 데이터 정리** : 데이터 테이블 전송 시 반드시 정수형으로 반올림 / 버림 처리하여 빌드 오류 방지

## 캐릭터 상태 제어 및 FSM 설계

### 상태, 전이조건, 행동의 상관성
* **상태** : 캐릭터가 점유하는 유일무이한 행동 단위이다.
* **전이조건** : 상태를 강제 이전하게 만드는 입력 기폭제 스위치이다.
* **행동** : 상태 진입, 도중, 이탈 단계에서 엔진이 사운드나 이펙트, 애니메이션을 렌더링하게 보정한다.

### FSM 검수 시 흔히 발견되는 3대 치명적 논리 결함
* 고립루프 및 복귀수단 누락
* 사망 상태 잠금 위반
* 비주얼 브레이크 예외

## 캐릭터 데이터 테이블 구조 설계

### 데이터를 쪼개야 하는 이유
* 수저통 정리의 법칙 : 종류별로 칸을 나누고 이름표를 붙이는 것이 정규화의 핵심
* 중복 제거와 최적화 : 분리하여 데이터 낭비를 막아야함.

### 핵심 식별자 : PK / FK
* **기본키** : 각 행을 유일하게 구분하는 고유 번호이다. 주민등록번호처럼 중복되지 않는 절대적인 ID 이다.
* **외래키** : 다른 테이블의 PK를 참조하는 연결고리이다. 이스탯은 어떤캐릭터의 것인가? 를 연결해준다.
* **복합키** : 두 개 이상의 열을 합쳐 고유성을 증명한다.

### 데이터 정밀 검수 지침
* 데이터 중복 과정 방지
* 네이밍 컨벤션 준수
* 순수 원시 타입 고수
* ID 코드 체계 확립
