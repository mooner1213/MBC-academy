# git(버전 관리 시스템)

## 버전 관리 시스템이란?

**버전관리시스템**은 소스코드, 문서, 웹사이트, 그래픽 파일 등

다양한 디지털 파일의 변화를 시간에 따라 기록 및 관리하는 **소프트웨어 도구**이다.

파일의 **과거 버전**으로 돌아가거나, **특정 버전**의 내용을 비교할 수 있다.


## 버전 관리 시스템의 주요 기능

1. **변경 이력 추적** : 파일의 모든 변경 사항을 **시간 순서대로 기록**
2. **협업 지원** : 여러 사용자가 동시에 파일을 수정할 수 있게 함.
3. **복구** : 이전 버전으로 되돌리거나, 특정 시점의 상태로 복구 가능
4. **비교** : 두 버전 간의 차이점을 비교 할 수 있다.
5. **분기 및 병합** : 독립적인 브랜치를 만들어서 별도로 작업 후, 병합 가능

## 버전 관리 시스템의 장점

1. **효율적인 협업** : 여러 사람이 동시에 같은 파일을 작업 시, 충돌을 최소화하고 효율적으로 관리 할 수 있다.
2. **이력 관리** : 모든 변경 사항이 기록 되므로, 언제든지 과거의 특정 시점으로 돌아갈 수 있다.
3. **백업 및 복구** : 작업 내용이 저장소에 안전하게 백업 되므로 데이터 손실을 방지할 수 있다.
4. **변경 사항 추적** : 누가 언제 어떤 변경을 했는지 추적이 가능하다.
5. **브랜치 관리** : 다양한 실험이나 기능 개발을 독립적으로 진행, 검토를 거쳐 메인 프로젝트에 병합이 가능하다.

## 대표적인 버전 관리 시스템

1. **Git** : **분산 버전 관리 시스템**으로, 현재 가장 널리 사용됨.
2. **Subversion(SVN)** : **중앙집중식 버전 관리 시스템**으로, Git이전에 많이 사용 되었음.
3. **mercurial** : Git과 유사한 분산 버전 관리 시스템.
4. **CVS** : 오래된 중앙 집중식 버전 관리 시스템.

## 버전 관리 시스템의 종류

1. **로컬 버전 관리 시스템(Local VCS)**
<img width="468" height="300" alt="image" src="https://github.com/user-attachments/assets/46de88e3-5bb8-425d-b328-84fbbbdee6d1" />

디렉토리에 파일을 복사하여, 버전을 관리하는 방식은 간단하므로, 자주 사용되지만, 실수로 삭제하거나,

파일을 잘못 고치는 문제 때문에 데이터베이스를 사용해 파일의 변경 정보를 관리하는 시스템을 만들었는데,

**로컬 버전 관리 시스템**이다.

여러 사람과의 협업 보다는, 개인 프로젝트에 적합, 컴퓨터가 고장나 내부 정보가 통째로 날아간다면,

복구할 방법이 없다는 단점이 존재한다.

2. **중앙집중식 버전 관리 시스템(Centralized VCS)**
<img width="470" height="279" alt="image" src="https://github.com/user-attachments/assets/4a5f32ac-44a7-4289-801a-3ee4086c9d0b" />

중앙 서버에서 모든 버전의 데이터를 관리 및 저장하며, 수정하기 위해서는 서버에 요청해 

파일을 받은 후 수정하고, 다시 서버에 올리는 방식이다.

로컬 버전 관리보다 협업이 쉬워지고 관리자가 누가 어떤일을 하고 있는지 알기 쉬운 장점이 있다.
<img width="377" height="277" alt="image" src="https://github.com/user-attachments/assets/b73a8506-5e53-4cd7-8a51-e2a9660c9798" />

하지만, 중앙 서버에서 관리를 하므로, 수정요청된 파일이 겹쳐버릴 수도 있다.

3. **분산 버전 관리 시스템(Distributed VCS)**
<img width="350" height="278" alt="image" src="https://github.com/user-attachments/assets/08efca74-a93f-4f04-ac15-3aaac665a633" />

서버뿐만 아니라 모든사용자가 모든 버전에 대한 히스토리를 가지고 있으므로, 로컬에서도 수정 이력과 내용을 볼 수 있다.

인터넷 연결 문제 때문에 작업에 지장을 받지 않으며, 만약 중앙 서버나 로컬 컴퓨터가 고장나도, 정상적인 로컬이 하나만 살아있으면

모든 데이터를 복원하는데 문제가 되지 않기 때문에, 가장 안정적이고 편리하다.

하지만 이는 로컬의 저장공간을 점유한다는 단점이 존재한다.


## Git 이란?

* **git**은 소프트웨어 개발에서 소스코드를 관리하기 위해 널리 사용되는 **분산 버전 관리 시스템**이다.
* 리눅스 커널 개발을 위해 2005년에 처음 개발 되었으며, 현재는 많은 개발자와 팀들이 사용중이다.

## git의 주요기능

* 버전관리 : 코드를 여러버전으로 관리하여, 언제든지 이전 버전으로 되돌아 갈 수 있다.
* 분산형 저장소 : 중앙 서버가 없어도, 로컬 저장소를 통해 모든 히스토리를 관리가 가능하다.
* 브랜치 : 기능을 독립적으로 개발하고 병합할 수 있도록 돕는 브랜칭 시스템을 제공한다.
* 협업 : 여러 개발자가 동시에 작업할 수 있도록 돕는 다양한 협업도구를 제공한다.

## git 의 공간

1. **Working Dircetory** : **WorkingSpace**라고도 하며, 프로젝트를 하는데 있어 작업을 하는 디렉토리를 의미한다. <br>실제 프로젝트 코딩하는 장소.<br>
2. **Staging Area(Index)** : 변경 사항을 임시로 저장하는 영역, <br>곧 **commit**할 파일에 대한 정보를 저장하고 있는 파일이다.<br>
3. **.git directory(Repository)** : 프로젝트 모든 버전에 대한 메타 데이터와 <br>객체 데이터베이스를 저장하는 장소, **git의 핵심**<br>
4. **Remote** : 원격창고, 코드를 호스팅하는 서버로 프로젝트 그룹 중 <br>원격 데이터 교환을 위해 존재하는 하나의 로컬이다.**클라우드**<br>

## git 의 상태

1. Modified : 데이터가 로컬 데이더 베이스에 안전하게 저장된 파일
2. Staged : 현재 수정한 파일을 곧 커밋할 것 이라고 표시한 상태의 파일
3. Committed : 데이터가 로컬 데이터 베이스에 안전하게 저장된 파일
