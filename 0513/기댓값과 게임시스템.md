# 게임설계의 핵심 : 기대값 이해하기

### 기댓값의 역설
> 인간은 왜 수학적으로 선택하지 않는가?

* **기댓값 배제의 원리** : 플레이어는 **항상 수학적으로 가장 유리한 기댓값**을 선택하지**않는다.**
* **정보의 무지와 인지적 한계** : **실질적인 기댓값을 계산**하거나 깨닫지 못해 **잘못된 선택**을 내리기도 한다.
* **본능적인 고통 회피** : **인간은 이득을 극대화**하기보다 **잠재적인 고통과 손실을 피하려는 경향**이 강하다.

### 운과 기술 : 예측의 매커니즘

* **가상적 기술과 실제 기술의 차이** : 순수한 운을 예측할 수 있다고 믿는 것은 **실체가 없는 가상적 기술**일 뿐이다.
* **완벽한 통제의 불가능성** : **모든 가능성을 완벽하게 컨트롤하려는 시도**는 현실이 아닌 상상속에서만 가능하다.
* **예측은 곧 기술** : **운의 흐름이나 상대방의 기술적 수준을 예측하는 행위는 실질적인 기술**에 해당한다.

### 현실의 게임시스템

 1. 현실의 문제에서 요소 추출하기
 2. 핵심 메카닉 정의

**자동차 트렁크에 짐 싣기**

 * 플레이어의 목표 설정
 * 공간효율과 선천적 만족감
 * 테트리스 주 메카닉의 기원

### 게임 오브젝트 속성 설계

**메카닉 vs 속성**

메카닉 - 오브젝트의 **동사**를 정의, **사용법을 제어하는 규칙**이며, 플레이어가 할 수 있는 **행동의 범위를 결정**한다.
속성 - 오브젝트의 **명사**를 정의, **규칙에 영향을 미치는 구체적인 값**이며, **게임 밸런싱의 핵심 데이터**가 된다.

### 실전분석 : 플레이어의 우주선

* 메카닉 - 좌우 이동, 미사일 발사, 충돌 시 파괴
* 속성 - 이동 속도, 발사 간격, 에너지, 크기(히트박스)

### 아이디어 구체화

**효율적인 브레인 스토밍 단계**

* **초기 브레인스토밍** : **제약없이 떠오르는 아이디어를 즉시 기록**한다. 양이 질을 결정하는 단계
* **푸른 하늘** : **현실성이나 기술적 한계를 무시**하고 **가장 창의적인 재미요소**에 집중한다.
* **속성조사** : **현실세계와 기존 게임들을 분석**하여, **객관적인 데이터 후보군을 수집**한다.

### 속성은행

* **개인 속성 은행** : 다양한게임에서 사용된 속성 리스트를 DB화하여 관리한다.
* **실제 세계 조사** : 현실 사물의 물리적 특징을 관찰하여 게임적 허용으로 변환한다.
* **래퍼런스 분석** : 성공한 장르게임들의 속성구조를 벤치 마킹하여 안정성을 확보한다.
* **창의적 결합** : 서로 다른 성격의 속성을 결합하여 독특한 게임 메카닉을 탄생시킨다.

### 속성정의 가이드라인

|고려사항|실무가이드|디자이너의 질문|
|-------|----------|----------------|
|명확한의미|누구나 동이랗게 이해할 수 있는 용어 사용| "이 값은 무엇을 의미하는가?"|
|구체적용도|시스템연산에 직접 참여하는 값만 유지|"어디에 사용되는가?"|
|메카닉용도|속성의 변화가 플레이의 변화로 직결|"메카닉과 밀접한가?"|

### 스프레드 시트 데이터

* 사전 작업 계획 : 작업 시작 전, 스프레드 시트로 수행할 작업을 미리 계획한다.
* 사용자 관점의 설계 : 내가 작성한 시트를 타인의 관점을 고려하여 가독성 높은 구조를 설계해야한다.
